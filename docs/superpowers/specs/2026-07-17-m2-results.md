## Gotchas found

- **WirePlumber refuses to route playback streams into `Audio/Source/Virtual` nodes** — `target.object` by name, by serial, and `connect(Some(node_id))` all ignored; stream falls back to the default sink (was blasting test tone into the AirPods). Fix: connect with NO AUTOCONNECT and manually `pw-link vc-live-out:output_MONO vc_mic:input_FL/FR` with retry. (The python client's own VC_Mic is fed by `module-loopback`, consistent with this policy.)
- The null-sink is stereo (`input_FL/FR`) despite `audio.position=[MONO]` — link mono output to both.
- System default source on this box IS the old VC_Mic → naive "use default mic" captures the wrong thing. Auto-pick first `alsa_input.*`; `--input <node.name>` overrides.
- pipewire crate 0.8 fails to build against pipewire 1.6 headers (spa_pod_builder layout) — need 0.10 + feature `v0_3_77`; bindgen uses ROCm SDK's libclang (paths in `native/.cargo/config.toml`, box-specific).

## Usage

```
cd ~/voice-changer
native/target/release/vc-live                 # defaults: hw mic -> vc_mic
native/target/release/vc-live --pitch 0 --block 2560 --ctx-left 4160
native/target/release/vc-live --tone          # self-test tone instead of mic
```
Discord: Settings → Voice → Input Device → "vc_mic". Stats print every 5 s.
