# M0 Decision: GPU Runtime

**Date:** 2026-07-17
**Hardware:** AMD Strix Halo (Radeon 8060S, gfx1151), RADV, Mesa 26.1.4, kernel 7.1.3-cachyos
**Method:** identical ONNX graphs + golden tensors from the python oracle (`native/tools/`), 20 warmup / 50–100 timed runs, p50/p95, correctness gates vs goldens. Bench code: `native/spike-ort`, `native/spike-burn`.

## Measured — 1 s @ 16 kHz input, fp32

| net | ORT CPU | ORT WebGPU | burn vulkan | burn wgsl | burn ndarray-cpu |
|---|---|---|---|---|---|
| contentvec | **35.0 ms** ✓ | 42.5 ms ✓ | not reached | not reached | 490.9 ms ✓ |
| rmvpe | **46.8 ms** ✓ | 574.4 ms ✓* | pads-blocked | pads-blocked | pads-blocked |
| fcpe | 8.0 ms ✓ | **6.6 ms** ✓ | 14.0 ms **✗ RMSE 6.6e-2** | same ✗ | 157.6 ms ✓ |
| synth (40k) | **77.8 ms** ✓ | 88.3 ms ✓ | **✗ DTypeMismatch panic** | same ✗ | 2383.5 ms ✓ |
| chain cv+fcpe+synth | **120.8 ms** | 137.4 ms | — | — | 3032 ms |

\* rmvpe on WebGPU = 86% MemcpyToHost thrash around CPU-partitioned GRU/STFT nodes (ORT profiling) — unusable there, fine on CPU.

## Block-scale sweep (ORT, fp32)

| window | CPU chain (cv+fcpe+synth) | WebGPU chain |
|---|---|---|
| 1.0 s | 121 ms | 137 ms |
| 0.5 s | 108 ms | 107 ms |
| 0.25 s | 60 ms | 112 ms |

WebGPU has a ~40–65 ms dispatch-overhead floor per net regardless of input size (arXiv 2604.02344 profile confirmed locally); CPU scales down with window size. At realtime window sizes CPU wins outright today.

## Findings that shaped the result

- **ORT graph capture**: inert for our graphs (CPU-partitioned nodes present). Static-shape + onnxsim'd synth (749 nodes vs 4773) benched **slower** on both EPs — simplification broke ORT fusion patterns. Dynamic export stays canonical for ORT.
- **fp16 (ORT)**: onnxconverter-common produced type-broken graphs on both nets (mixed-type Mul; Cast retype), second attempt hung. Timeboxed out; not load-bearing for the decision (dispatch floor, not FLOPs, dominates WebGPU).
- **burn-onnx codegen is correct**: all three nets pass gates on the ndarray backend — the whole RVC graph (attention, flow, NSF vocoder) imports and runs right. Two codegen bugs worked around: runtime-Pad unsupported (static re-export; rmvpe left blocked) and reverse-Slice emitted as out-of-range i32 literal (build.rs rewrites to `flip`, see `native/spike-burn/build.rs`).
- **burn wgpu backend is numerically broken for these graphs in 0.21**: fcpe latent RMSE 6.6e-2 and synth DTypeMismatch panic, **identical on Vulkan/SPIR-V and WGSL** → bug in the shared CubeCL/Fusion stack, not the SPIR-V compiler. Its CPU (ndarray) backend is correct but 20–30× slower than ORT CPU.

## Paper-eliminated candidates (from research phase)

- **ncnn**: Deconvolution1D, GRU, ConvolutionDepthWise1D have no Vulkan impl (verified `src/layer/vulkan` listing, 2026-07) — the NSF-HiFiGAN upsampler and HuBERT positional conv partition to CPU. Custom-layer cost > adoption cost of ORT/burn. Rust bindings stale (2023).
- **ggml**: no GRU op; conv-transpose-1d Vulkan present but COL2IM_1D missing; hand-port = weeks (audio.cpp/TTS.cpp both vendor patched ggml). Retained as post-v1 endgame option if we ever need to own kernels outright.

## Decision

- **Runtime: ONNX Runtime via the `ort` crate (2.0.0-rc.12, ORT 1.24.2). Language: Rust.**
- **Default EP: CPU.** It wins every net at realtime window sizes and passes all gates.
- **WebGPU EP ships as an experimental GPU toggle**, revisited each ORT release: it is the Vulkan vendor-neutral path we want, already fastest for fcpe, and upstream is actively landing dispatch-overhead work (graph capture, fused attention). Silent-CPU-fallback detection (per-stage micro-bench) as designed in the spec.
- **Pitch default: fcpe** (8 ms CPU / 6.6 ms GPU vs rmvpe 47 ms; no GRU; quality parity except extreme noise per FCPE paper). **rmvpe = quality-mode toggle, CPU-pinned.**
- **burn: watch-list.** Recheck at burn 0.22+ — if the wgpu numeric bugs die, it becomes the credible single-stack Vulkan path (codegen already proven correct). The spike harness re-runs in minutes.

## Consequences for M1

- Realtime pipeline budget on this box (fp32 CPU, 0.25 s window): cv 24 + fcpe 4.6 + synth 31 ≈ **60 ms compute per hop** before pipelining — workable for a 64–128 ms block with overlap; M1 measures the real chunked pipeline and tunes context/window sizes.
- Keep dynamic-axis ONNX exports for ORT; static exports exist for future burn/graph-capture use.
- ORT intra-op thread count, window sizing, and contentvec-on-WebGPU offload (stable 42 ms, frees CPU for synth) are the first M1 tuning levers.
- The 3-model artifact set + goldens + gates in `native/` are the permanent regression harness.
